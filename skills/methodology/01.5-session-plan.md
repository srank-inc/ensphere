# Session 01.5: Session Applicability Plan

## Objective

Convert the Session 01 inventories into an auditable plan for Sessions 02–08.
Every decision must cite affirmative evidence or preserve the uncertainty.

## Inputs

- `config.md`
- `progress.md`
- `01-recon/report.md`
- `01-recon/target-profile.yaml`
- inventory and evidence artifacts referenced by recon

Do not plan from the target-type label alone.

## Preflight Gate

Confirm the selected target/profile matches the configured URL, source path,
environment, backend inventory, and scope. Confirm availability of required
accounts, roles, tenants, test objects, regions, provider access, protocols,
callbacks, and a stable live target.

If recon lacks provenance or contains material target ambiguity, return to
Session 01 or mark the affected decisions `uncertain`/`blocked`.

## Decision Method

For each session:

1. Cite the inventory rows demonstrating whether relevant surface exists.
2. Name the exact planned assets, endpoints, roles, inputs, and controls.
3. List required inputs and whether each is available.
4. Choose `run`, `limited`, `blocked`, `skip`, `force`, `uncertain`, or
   `not_applicable` using the shared contract.
5. Assign coverage only after checking the completeness criteria below.
6. Record the consequence of every missing input.

Applicability evidence:

| Session | Affirmative surface |
|---------|---------------------|
| 02 Injection | User-controlled data reaches a server-side parser, query, command, template, path, XML/object decoder, or equivalent sink candidate. |
| 03 Authentication | Login, session, token, password reset, MFA, OAuth/SSO, API key, or identity transition exists. |
| 04 Authorization | Multiple users/roles/tenants, owned objects, privileged functions, or workflow invariants exist. |
| 05 XSS | User-controlled content reaches an HTML/DOM/markdown/email/PDF or other script-capable rendering context. |
| 06 SSRF | A server-side fetcher, webhook, importer, previewer, callback, remote-media loader, or renderer accepts a URL or network destination. |
| 07 Cloud | Authorized cloud/Kubernetes/IaC assets or scanner artifacts are in scope. |
| 08 API | REST, GraphQL, RPC, gRPC, WebSocket, SSE, webhook, or message API surface exists. |

## Coverage Gate

Use `full` only when every necessary input for the planned surface is present,
including applicable source and environment, accounts and roles, tenants and
owned objects, regions/projects, protocols, test data, callbacks, and target
stability. Otherwise choose the precise label (`partial`, `blocked`,
`source_only`, `black_box_only`, `client_only`, or `cloud_only`) and state the
impact.

`not_applicable` requires affirmative inventory evidence that the category is
absent. Failed discovery, missing credentials, or no observed result is not
sufficient.

Human overrides must record who/what supplied the override, time or artifact
reference, reason, accepted gap, and any tighter scope or safety limit.
