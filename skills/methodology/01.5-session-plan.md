# Session 01.5: Session Applicability Plan

Create the assessment plan that decides which sessions run, skip, block, or
operate with limited coverage. This session runs after Recon and before any
category-specific testing.

Read first:
- `skills/shared/workflow-contract.md`
- `ensphere-pentest/config.md`
- `ensphere-pentest/progress.md`
- `ensphere-pentest/01-recon/report.md`
- `ensphere-pentest/01-recon/target-profile.yaml`

## Output Artifacts

Write:
- `ensphere-pentest/01.5-session-plan/assessment-plan.yaml`
- `ensphere-pentest/01.5-session-plan/report.md`

Copy or symlink is not required, but the canonical plan should also be available
as:

```text
ensphere-pentest/assessment-plan.yaml
```

If direct file copying is not available in the current agent environment, write
the same content to both paths.

If `ensphere run plan` already created a draft `assessment-plan.yaml`, read it
as a starting point only. Update decisions, reasons, coverage labels, and
required inputs from Session 01 Recon evidence before marking Session 01.5 done.
Do not preserve a config-only draft decision when Recon contradicts it.

## Phase 0: Preflight Checks

1. Confirm `ensphere-pentest/01-recon/report.md` exists.
2. Confirm the authorization statement exists in `config.md`.
3. Confirm target type, source mode, live URL availability, and cloud scope.
4. Confirm whether credentials are present.
5. Confirm whether the target is one service or an ambiguous monorepo.

If the monorepo target is ambiguous, mark Session 01.5 `BLOCKED`, explain the
deployable choices, and ask the user to choose the target before continuing.

## Phase 1: Target Classification

Classify the selected target as one of:

| Target Type | Meaning |
|-------------|---------|
| `web_app` | Browser UI and network backend are in scope. |
| `api_backend` | API or service backend is in scope without primary browser UI. |
| `static_site` | Static/browser-only site, possibly with remote APIs. |
| `mobile_client_remote_backend` | Mobile client calls a remote backend. |
| `mobile_client_offline` | Mobile client has no server-side target supplied. |
| `desktop_or_extension_client` | Desktop, Electron, or browser extension client. |
| `cloud_only` | Cloud, Kubernetes, or IaC target with no app HTTP surface. |
| `library_or_cli` | Library or CLI without network-exposed service. |

Record:
- Target type
- Source mode: `white_box`, `black_box`, `source_only`, or `live_only`
- Coverage label from `workflow-contract.md`
- Rationale with evidence references from Recon
- Backend/API inventory extracted from client code, browser traffic, OpenAPI,
  GraphQL, or mobile traffic
- Client-only exposure review notes when no server-side target exists

## Phase 2: Session Decisions

For each session 02 through 08, assign a decision from
`workflow-contract.md`:

| Session | Default Run When | Default Skip/Block When |
|---------|------------------|-------------------------|
| 02 Injection | Server-side input, parser, database, command, file, template, XML, NoSQL, LDAP, XPath, or upload surface exists. | Client-only or static-only with no backend. |
| 03 Auth | Login, session, token, OAuth, SSO, MFA, API key, or credential flow exists. | Fully public target with no identity mechanism. |
| 04 Authz | Roles, tenants, ownership, admin routes, object IDs, or workflow permissions exist. | No role/object boundary or missing required test accounts. |
| 05 XSS | Browser-rendered HTML, DOM sinks, WebViews, or rendered user content exist. | API-only with no rendered client in scope. |
| 06 SSRF | URL fetchers, webhooks, importers, previewers, renderers, callbacks, or metadata-reachable cloud surface exists. | No outbound request sinks or URL-controlled fetch behavior found. |
| 07 Cloud | Cloud provider, Kubernetes, IaC, provider credentials, or scanner output is in scope. | No cloud/IaC/provider assets in scope. |
| 08 API | REST, GraphQL, gRPC, WebSocket, SSE, webhook, or RPC surface exists. | No API/protocol surface in scope. |

When uncertain, default to `run` unless the human explicitly accepts the risk
of skipping.

## Phase 3: Edge-Case Handling

Handle these cases explicitly:

- **Source-only, no live URL**: allow source review and sink discovery, but mark
  dynamic verification as `blocked` or `partial`.
- **Live URL, no source**: use black-box path and disable `ensphere scan` and
  `ensphere sinks`.
- **Missing credentials**: run public-surface checks only; mark auth, authz, and
  protected API coverage as `blocked`.
- **SSO/MFA/magic links**: require supplied test accounts and session setup
  notes. Do not bypass identity controls unless explicitly scoped.
- **Multi-role/multi-tenant**: require a role and tenant matrix before Session
  04. If unavailable, mark authz coverage `blocked` or `partial`.
- **Third-party providers**: record boundaries and do not probe external
  providers unless explicitly in scope.
- **Async/webhook/queue effects**: require correlation IDs, callback logs, or
  delayed verification windows.
- **Client-only targets**: stop normal web/API dynamic assessment workflow and write a
  client exposure review recommendation.
- **Static/client-only with no API surface**: mark Sessions 02, 03, 04, 06, and
  08 `not_applicable`; run only client exposure or DOM review that is genuinely
  in scope.
- **Mobile client with remote backend**: record every extracted backend base URL,
  protocol/kind, source, and evidence reference before enabling backend
  sessions. If backend inventory is missing, mark Sessions 02, 03, 04, 06, and
  08 `blocked` until the target API is identified.
- **Cloud-only targets**: run Session 07 and mark app sessions not applicable
  unless HTTP surface exists.

## Assessment Plan Schema

Write YAML with this shape:

```yaml
schema_version: 1
target:
  type: api_backend
  source_mode: white_box
  coverage_label: full
  classification_source: 01-recon/target-profile.yaml
  classification_confidence: high
  recon_profile_path: 01-recon/target-profile.yaml
  url: https://staging.example.com
  scope:
    - staging.example.com
  rationale:
    - "Session 01 found REST API endpoints under /api/v1."
  backend_inventory:
    - name: primary-api
      base_url: https://api.example.com
      kind: rest
      source: JavaScript bundle analysis
      evidence_refs:
        - "01-recon/report.md#backend-inventory"
  client_exposure_review:
    - "Review hardcoded endpoints and embedded keys if no backend is added to scope."
  signals:
    api_surface: true
    server_side_surface: true
    authentication: true

sessions:
  02-injection:
    decision: run
    applicability: applicable
    coverage_label: full
    reason: "User-controlled query and JSON body fields reach DB-backed handlers."
    evidence_refs:
      - "01-recon/report.md#input-vectors"
  03-auth:
    decision: run
    applicability: applicable
    coverage_label: full
    reason: "Login, refresh, and password reset endpoints found."
    evidence_refs:
      - "01-recon/report.md#authentication"
  04-authz:
    decision: blocked
    applicability: applicable
    coverage_label: blocked
    reason: "Role boundary exists but only one test account is available."
    required_input:
      - "At least one lower-privilege and one higher-privilege account."

exploitation:
  enabled: false
  selected_findings: []
  max_risk: 3
  cleanup_required: true

human_overrides: []
created_by: "Ensphere Session 01.5"
```
